\section{Implementation Details}
\label{app:constants}

Table~\ref{tab:constants} lists the implemented defaults.
Execution sampling is used only to compute reinforcement-learning rewards; it
does not construct the synthetic SFT corpus.  SFT synthesis, RL, and inference
share the rollout--combine--filter implementation: the same conjunction
splitting, response cap, normalization, candidate combination, iterative
syntax filter, optional AST deduplication, and Houdini pruning.  SFT
serializes the filtered combination, RL scores the responses that populate it,
and inference restores \(Q\) only after filtering.  Inference does not
construct execution examples.

\subsection{Negative-Trace Sampling}
\label{app:negative-sampling}

Algorithm~\ref{alg:negative-sampling} summarizes the sampler used for RL.
\(\operatorname{Trace}\) records real loop-head states and, after each genuine
exit, continues the real loop body to obtain one post-exit trace.
\(\operatorname{Perturb}_{1,2}\) applies the configured single-variable and
pairwise changes, while \(\operatorname{RangeEscape}\) moves one variable just
outside its sampled range.  The exact perturbations and budgets are those in
Table~\ref{tab:constants}.

\begin{algorithm}[H]
\caption{Target-hidden negative-trace sampling}
\label{alg:negative-sampling}
\begin{algorithmic}
\alginput{masked loop \(\mathcal L=(P,B,S)\), input schedule \(U\), configuration \(\Theta\)}
\algoutput{reachable states \(\mathcal P\), negative traces \(\mathcal N\)}
\algline \(\mathcal T,\mathcal C_{\rm post},c
  \leftarrow\operatorname{Trace}(\mathcal L,U,\Theta)\)
  \cmnt{\(c\): some run was capped}\\
\algline \(\mathcal P\leftarrow\operatorname{UniqueHeads}(\mathcal T)\);
  \quad \(M\leftarrow\operatorname{SafeModifiedVars}(S)\)\\
\algline \kw{if} \(M=\varnothing\) or \(S\) has unsupported state
  \kw{then return} \((\mathcal P,\varnothing)\)\\
\algline \(\mathcal S\leftarrow
  \operatorname{StratifiedSample}(\mathcal P)\)\\
\algline \(C_{\rm rel}\leftarrow
  \operatorname{Perturb}_{1,2}(\operatorname{Dense}(\mathcal S),M,\Theta)\)\\
\algline \kw{if} \(\neg c\) \kw{then}
  \(C_{\rm rel}\leftarrow C_{\rm rel}\cup
  \operatorname{Perturb}_{1,2}(\operatorname{Terminals}(\mathcal T),M,\Theta)\)\\
\algline \(C_{\rm range}\leftarrow
  \operatorname{RangeEscape}(\mathcal S,M,\mathcal P,\Theta)\) if \(\neg c\),
  else \(\varnothing\)\\
\algline \((C_{\rm rel},\mathcal C_{\rm post},C_{\rm range})
  \leftarrow\operatorname{Clean}_{\mathcal P}
  (C_{\rm rel},\mathcal C_{\rm post},C_{\rm range})\)\\
\algline \(N_{\rm rel},\mathcal N_{\rm post},N_{\rm range}
  \leftarrow\operatorname{BudgetAndRoundRobin}
  (C_{\rm rel},\mathcal C_{\rm post},C_{\rm range},\Theta)\)\\
\algline \(\mathcal N\leftarrow
  \{\langle s\rangle:s\in N_{\rm rel}\}\cup\mathcal N_{\rm post}
  \cup\{\langle s\rangle:s\in N_{\rm range}\}\)\\
\algline \kw{return} \((\mathcal P,\mathcal N)\)\\
\end{algorithmic}
\end{algorithm}

\(\operatorname{Clean}_{\mathcal P}\) removes observed reachable states,
possible fresh loop entries, duplicates, and unsupported candidates, using
family priority relation, post-exit, then range.  A cleaned post-exit
continuation remains one trace; relation and range candidates become singleton
traces.  Within the relation budget, candidates that preserve the guard truth
value and remain inside the sampled coordinate ranges are selected first.

\section{Generation Prompt}
\label{app:prompt}

The same generation template proposes the responses later combined during SFT
synthesis, RL, and inference.  Any assertion is stripped before the program is
inserted.  General annotation rules are supplied separately by
\texttt{system\_prompt.txt}.

\begin{promptbox}[Generation prompt]
\begin{lstlisting}[style=promptstyle]
You are given a C function. Produce the strongest inductive ACSL loop
invariants that capture the loop's behavior (conservation/relational laws
+ tight progress bounds). Output ONLY invariant lines, each formatted
exactly as:
loop invariant <expr>;
Output at most 20 invariant lines.

Program:
{program}
\end{lstlisting}
\end{promptbox}

\section{Training Interface}
\label{app:service}

The training service is packaged as a self-contained, CPU-only container with
gcc, the verifier, Why3, and Z3.  It exposes \texttt{POST /reward}, accepting
program source and an array of model responses.  The implementation retains
the following field names for compatibility:
\begin{lstlisting}[style=promptstyle]
{program, n_positives, n_negatives, filter_mode,
 reward_mode, rollout_rewards[], base[], hard_bonus[],
 redundant_clauses[], redundancy_penalty[],
 generated[], accepted[], overflow[], overflow_penalty[],
 rollouts[], batch_score, should_reroll}
\end{lstlisting}
Responses may be raw LLM text, invariant lists, or annotated code; parsing is uniform.
An offline scorer provides the same generation reward over JSONL/Parquet
rollout dumps.

\section{Method}\label{sec:method}
%% ============================================================

\subsection{Overview}

For a verification instance \((P,Q)\), the generator receives the
target-masked program \(P=(\phi_{\mathrm{pre}},B,S)\).
One sampled response, or \emph{rollout},
\(A=(a_1,\ldots,a_L)\), is an ordered list of parsed invariant clauses.
A training group \(\mathcal A=\{A_1,\ldots,A_G\}\) contains \(G\) responses
for the same program.  Only the first \(K\) clauses of each response are used:
\[
  \bar A=(a_1,\ldots,a_{\min(L,K)}),\qquad
  o(A)=\max(0,L-K).
\]

Given a set of clauses \(X\), \(\mathsf H_P(X)\) denotes the subset retained
after syntax checking and Houdini filtering with Frama-C/WP.
Execution provides reachable loop-head states \(\mathcal P\) and synthetic
negative traces \(\mathcal N\).  A negative trace may contain several witness
states from one perturbed execution.  We write
\(\mathrm{rej}(X)\subseteq\mathcal N\) for the negative traces on which at
least one clause in \(\mathsf H_P(X)\) is false.

The method has four parts.  First, candidate responses are normalized,
combined, optionally repaired, and filtered by the verifier.  This pipeline is
used to construct synthetic SFT pairs.  Program executions then provide a
separate target-independent signal for reinforcement learning.  Inference
reuses the candidate pipeline without SFT serialization, execution sampling,
or reward computation.

%% ------------------------------------------------------------
\subsection{Candidate Generation and Verification}
\label{sec:method:core}

The model emits scalar ACSL clauses of the form
\texttt{loop invariant <expr>;}.  Each response is capped at \(K\) parsed
clauses, normalized, and deduplicated.  For a group of responses, the initial
candidate set is
\[
  X_0=\bigcup_{i=1}^{G}\bar A_i.
\]
An optional repair round receives only syntax, scope, establishment, and
preservation verdicts from the target-masked program.  Its response \(R_t\)
can add clauses but cannot remove existing candidates:
\[
  X_{t+1}=X_t\cup R_t.
\]

The filter \(\mathsf H_P(X)\) first removes malformed invariant lines and then
runs Houdini over Frama-C/WP~\citep{flanagan2001houdini,framac}.
Houdini repeatedly removes clauses whose establishment or preservation
obligations fail and returns an inductive subset.  During reward computation,
sampled reachable states provide a cheap pre-filter for out-of-scope or
obviously false clauses.  Inference skips this optimization.  In both cases,
Frama-C/WP is the source of soundness.

Training evaluates \(\mathsf H_P(\bar A_i)\) for each response,
\(\mathsf H_P(X_0)\) for the union, and
\(\mathsf H_P(X_t\cup R_t)\) when learning repair.
Inference applies the same cap, normalization, union, repair feedback, and
Houdini filter.  The difference is downstream: training computes rewards from
execution examples, whereas inference inserts the filtered clauses into the
full program and checks the restored \(Q\).

\subsection{Synthetic Data for Supervised Fine-Tuning}
\label{sec:method:sft}

For each target-masked program \(P\), the data generator samples a group of
candidate responses and applies the same cap, normalization, union, optional
repair, and Houdini filter defined above.  When the resulting set
\(\mathsf H_P(X)\) is nonempty, it is serialized as a canonical ACSL response
and paired with \(P\):
\[
  \mathcal D_{\mathrm{SFT}}
  =\left\{\bigl(P,\operatorname{serialize}(\mathsf H_P(X))\bigr)\right\}.
\]
The original target \(Q\) is not included in the input, feedback, or output of
this construction.  Supervised fine-tuning therefore teaches the model to
imitate verifier-accepted invariant sets produced by the same aggregation and
filtering procedure later used at inference.

This synthetic SFT corpus is distinct from the execution examples introduced
next.  An SFT target is a verified ACSL invariant response; a positive or
negative execution state is used only to compute the reinforcement-learning
reward and is never serialized as an SFT answer.

\subsection{Execution-Based Training Examples}
\label{sec:method:sampler}

The execution sampler never reads an assertion or postcondition.  It supports
one braced \texttt{while} loop over scalar integer parameters, locals, and
file-scope variables.  It instruments the loop, compiles it with \texttt{gcc},
and records loop-head valuations for a deterministic, precondition-checked
input sweep.  The recorded states form the positive set \(\mathcal P\).
Runs continue to a genuine loop exit; hitting the iteration cap marks a run as
incomplete and disables any construction that requires reliable terminal or
range information.

The sampler constructs three kinds of negative examples:
\begin{itemize}
  \item \textbf{Relational perturbations.}  Single-variable and pairwise
  \(\pm\{1,2\}\) changes are applied to densely observed states.  These
  examples target relations such as \(x+y=n\) that may hold even when each
  variable has a broad range.
  \item \textbf{Post-exit continuations.}  After an observed genuine exit, the
  loop body is executed for additional steps.  The continuation preserves the
  program's transition relation while moving beyond the actual run.
  \item \textbf{Range perturbations.}  One variable is moved beyond the range
  observed for that variable.  These examples test whether a candidate
  captures useful bounds.
\end{itemize}

These are training candidates, not proofs of global unreachability.
Any candidate equal to an observed reachable state is removed.  The sampler
also removes states that may be feasible fresh loop entries for the recorded
input, and it excludes variables affected by unsupported or
oracle-dependent behavior.  Unsupported block-local state, pointers, arrays,
or function calls disable synthetic negatives; if no safe variable remains,
the program contributes positive states only.  Exact sampling schedules,
budgets, perturbation sizes, and fallback conditions are reported in
Appendix~\ref{app:constants}.

\subsection{Reward and Training}
\label{sec:method:reward}

For response \(A_i\), let
\(R_i=\mathrm{rej}(\bar A_i)\) be the negative traces rejected after Houdini
filtering.  Its negative rejection rate is
\[
  \mathrm{coverage}(A_i)=\frac{|R_i|}{|\mathcal N|}.
\]
To reward complementary responses, define the frequency with which a negative
trace \(n\) is rejected in the group and a bonus for less common rejections:
\begin{align}
  f(n) &= \sum_{j=1}^{G}\mathbf 1[n\in R_j],\\
  \mathrm{bonus}(A_i)
  &=\frac{1}{|\mathcal N|}
    \sum_{n\in R_i}\left(1-\frac{f(n)}{G}\right).
\end{align}
The first term rewards overall strength; the second rewards a response for
contributing behavior not already covered by most of its peers.  A response
need not contain a complete proof to receive credit.

We do not penalize a unique clause merely because it adds no independently
observed coverage: it may support another clause or be needed for the hidden
target.  We only count conservative syntactic and local algebraic duplicates,
\[
  d_{\mathrm{dup}}(A)
    =|\bar A|-|\mathrm{dedup}(\bar A)|.
\]
The deduplication key normalizes comparison direction, equality sides,
parentheses, immediate commutative operands, harmless identities, and Boolean
association.  It deliberately avoids transformations whose validity depends
on stronger arithmetic assumptions.

The generation reward is
\begin{equation}
\label{eq:generation-reward}
r_{\mathrm{gen}}(A)=
w_c\,\mathrm{coverage}(A)
+w_g\,\mathrm{bonus}(A)
-w_d\,d_{\mathrm{dup}}(A)
-w_o\,o(A),
\end{equation}
with default weights \((w_c,w_g,w_d,w_o)=(1.0,0.3,0.02,0.05)\).
Clauses after the cap \(K\) receive no coverage and incur the overflow cost.
Malformed and non-inductive clauses are removed before reward computation, so
one failed clause does not erase useful clauses in the same response.

The union also receives the diagnostic rejection rate
\(|\mathrm{rej}(X_0)|/|\mathcal N|\), which is used to decide whether another
group should be sampled.  If no negative examples can be constructed safely,
the reward falls back to binary inductiveness: a nonempty response receives one
only when all of its retained clauses pass Houdini.

Repair is trained separately.  For a current candidate set \(X\) and capped
repair response \(R_i\), its reward is the improvement in negative rejection:
\begin{align}
  \mathrm{gain}_i
  &=\mathrm{coverage}(X\cup R_i)-\mathrm{coverage}(X),\\
  r_{\mathrm{ref},i}
  &=\mathrm{gain}_i-w_o\,o(R_i).
\end{align}
The existing set \(X\) is not truncated.  Generation and repair examples are
mixed in the same policy update, training the two model actions used during
deployment.

\subsection{Inference}
\label{sec:method:inference}

At inference, the model receives the target-masked program and returns \(n\)
candidate responses.  Each is capped at \(K\) clauses, and the normalized
clauses are combined into \(X_0\).  Inference does not construct positive or
negative execution examples.

When repair is enabled, Frama-C/WP reports target-independent syntax, scope,
establishment, and preservation failures.  A stateless prompt asks the model
to repair failed clauses or add supporting invariants.  Each repair is capped
before it is added to the candidate set.  Repair stops when all clauses pass,
the set reaches a fixed point, or the round budget is exhausted.

Finally, \(\mathsf H_P\) filters the accumulated candidates on the
target-masked program.  The retained invariants are inserted into the untouched
full program, \(Q\) is restored, and Frama-C/WP checks every invariant and
target obligation.  If verification fails, the system may sample another
response group up to its configured retry budget.  No sampled state or
training reward participates in this final decision.
